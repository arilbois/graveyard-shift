# Demo and submission checklist

Suggested demo structure (<3 minutes; target about 2m40s):
- 0:00–0:20: developer human problem, concise sourced context, no unsupported health claims.
- 0:20–0:35: tagline and Kiro IDE extension launch.
- 0:35–1:15: genuine activity signals, sidebar, reminders and snooze/break.
- 1:15–1:55: visibly labeled DEMO MODE accelerate ignored reminders → zombie stages → The Last Human panel.
- 1:55–2:15: confirmed rest → recovery, motion/sound accessibility.
- 2:15–2:35: show `.kiro` specs, steering, hooks, generated test results and what Kiro materially contributed.
- 2:35–2:45: closing tagline and project install link.

Must have before submission:
- Valid public GitHub repository with root `.kiro/` not gitignored; open-source LICENSE at root; code, original/licensed assets, installation and testing instructions.
- Actual working extension; provide VSIX build/release or reproducible test-build and instructions, free for judges through judging period.
- Public YouTube video under 3 minutes showing actual product functioning in Kiro IDE; no copyrighted sound/music/art without permission.
- Devpost description, team/category details, real screenshots, Kiro usage retrospective including tangible effects of specs, steering, hooks and tests.
- Any student bonus fields if eligible.

Deadline: Dec 4, 2026 at 2:00 PM PST = Dec 5, 2026 5:00 AM WIB. Submit before last day if possible.
